# ADR-0006: CI on GitHub Actions

- Status: Accepted for CI; CD is planned (see Consequences)
- Date: 2026-10-23
- Related: AGENTS.md section 10; NFR Security (secrets, dependencies), Maintainability

## Context

AGENTS.md section 10 lists what CI must run on every PR: format, lint, unit, widget and golden tests, coverage thresholds, migrations on a fresh database with RLS tests, preset validation, secret scanning, dependency scanning, and iOS and Android debug builds.

## Decision

`.github/workflows/ci.yml` runs these jobs on every pull request and every push to `main`:

| Job | Checks |
| --- | --- |
| `app` | `pub get --enforce-lockfile`, generated code up to date, `dart format`, `flutter analyze --fatal-infos --fatal-warnings`, `flutter test --coverage` (includes goldens), coverage gate |
| `android-build` | `flutter build apk --debug` |
| `functions` | Prettier, `wrangler types --check`, `tsc`, ESLint with zero warnings, Vitest in `workerd` with coverage thresholds |
| `database` | `supabase db start` (applies every migration to a fresh database), `supabase test db` (pgTAP), `supabase db lint` |
| `secrets` | gitleaks over the full history |
| `dependencies` | OSV-Scanner over `pubspec.lock` and both `package-lock.json` files |

- Third-party Actions are pinned to commit SHAs with the version in a comment. Dependabot updates them weekly.
- The workflow token is read-only by default. Only the OSV job gets `security-events: write` to upload SARIF.
- Preset schema validation is added in M3, when `presets/` gets content.

## Consequences

- The iOS build job was removed when iOS was deferred (ADR-0009). Restore it on a `macos-latest` runner when iOS work resumes.
- gitleaks-action needs a free `GITLEAKS_LICENSE` secret if the repo moves to a GitHub organization.
- **CD (not built in M0):** merges to `main` deploy to staging (Workers via `wrangler deploy --env staging`, migrations via `supabase db push`) and ship Play internal testing builds with fastlane (TestFlight when iOS resumes, ADR-0009). This needs the Supabase projects, a Google Play developer account and signing keys. It's tracked as an M0 follow-up and needs the open decisions in ADR-0007.
