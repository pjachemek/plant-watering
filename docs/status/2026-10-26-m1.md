# Status: M1 NFC spike, 2026-10-26

Branch `m1-nfc-spike`, based on `m0-foundations`. Android only (ADR-0009).

## Done

- **Tag token and link** (`features/scan/domain/`): 128-bit secure token, fixed 22 base62 characters, redacted in logs; strict parser for `https://plants.pampait.pl/p/{token}`.
- **Android dispatch:** `NDEF_DISCOVERED` and verified App Link (`autoVerify`) intent filters for `/p/`, the `NFC` permission, and NFC declared optional.
- **NFC service:** `NfcService` interface with typed failures. The `nfc_manager` implementation writes one URI record (47 bytes, fits NTAG213), asks before overwriting, checks writability and capacity, reads back to verify, and maps Android errors to messages.
- **Debug-only NFC test screen** (`/dev/nfc`, NFC icon on the plant list in debug builds): write a test sticker, read a sticker, open the tag route.
- **Worker:** serves `/.well-known/assetlinks.json` and `/.well-known/apple-app-site-association` as JSON, a placeholder `/p/{token}` page, and the production custom-domain route.
- **Checks (all local):**
  - App: analyzer clean, 124 tests, coverage 93.6% overall and 100% for the domain layer.
  - Goldens: regenerated on Linux.
  - Worker: 14 tests, 100% line coverage, lint and type check clean.
- **Emulator** (no NFC hardware): a cold start from an NFC intent lands on the tag screen; a verified App Link opens the app with no chooser, warm and cold; the NFC screen shows the "can't read NFC" message.
- **Docs:** [ADR-0010](../adr/0010-nfc-read-write.md), [NFC test matrix](../testing/nfc-test-matrix.md), [deploy guide](../deploy.md).

## Next step

Deploy the Worker, then run the test matrix and fill in "Device findings" in ADR-0010. That closes M1. Then M2 (data and sync).

## Risks

- **Chooser on real scans:** Chrome also registers `NDEF_DISCOVERED` for every `https` URL, so a real tag scan may show "Open with: Plant NFC / Chrome". That would break FR-1's "no extra taps". The options are in ADR-0010; the test matrix (row 12) decides.
- The emulator with software graphics is slow (8–9 s cold starts in debug builds) and its System UI keeps freezing. Performance targets must be measured on real phones with release builds.
