# Status: M0 Foundations, 2026-10-23

## Done

- Monorepo layout: `app/`, `functions/`, `supabase/`, `web/`, `presets/`, `docs/adr/`, plus `tools/flutter.Dockerfile`.
- **App** (Flutter 3.47.7): design tokens, light and dark Material 3 themes, ARB localisation, go_router with `/p/:tagToken`, Riverpod code generation, Sentry with PII scrubbing (off without a DSN), `Result` type, placeholder plant list and tag screens.
- **Platform config:** minimum iOS 16 and Android API 26. Android blocks cleartext (debug allows only the local Supabase stack) and turns backups off.
- **App checks (verified locally in Docker):** analyzer clean with `--fatal-infos`; 54 tests pass, covering token contrast, tap-target, label and contrast guidelines, 200% text, deep links, the PII scrubber and three goldens; coverage 94% against a 70% gate.
- **Workers (verified locally):** Hono app with security headers, `/health`, Sentry with PII scrubbing. Prettier, `tsc`, ESLint (strict, zero warnings) and `wrangler types --check` all clean. 6 Vitest tests pass in `workerd`; coverage 100% of lines.
- **Supabase (verified locally):** `supabase init`, Edge Functions disabled, pgTAP smoke test passes on a fresh Postgres 17, `db lint` clean.
- **Android debug APK builds** (verified in Docker). **iOS is deferred** ([ADR-0009](../adr/0009-defer-ios.md)); the `ios/` project is kept but nothing builds it.
- **App launches on the Android emulator** (M0 exit, Android only per ADR-0009): debug build installed on `Medium_Phone_API_37.0` (API 37); the plant list empty state renders correctly. Start the emulator with `-no-snapshot -gpu swiftshader_indirect`; the default launch hangs on this machine.
- **CI:** `.github/workflows/ci.yml` (app, Android build, Workers, database, gitleaks, OSV), Dependabot and a PR template. A local gitleaks scan found no leaks.
- **Docs:** ADRs 0001–0009, README with setup in 15 minutes or less.

## Not done / blocked (needs the product owner)

- **CI has never run on GitHub.** The repo has no remote yet.
- **Three Supabase projects** (`dev`, `staging`, `prod`) and **Sentry projects** must be created in those accounts. Placeholders: `STAGING_PROJECT_REF`, `PROD_PROJECT_REF`, `SENTRY_DSN`.
- **CD** (staging deploy, Play internal testing via fastlane) needs a Google Play developer account and signing keys.
- **Open decisions** in [ADR-0007](../adr/0007-provisional-open-decisions.md). Flutter, the domain (`plants.pampait.pl`) and the bundle ID (`pl.pampait.plantnfc`) are confirmed in [ADR-0008](../adr/0008-confirmed-framework-domain-bundle-id.md). Still needed before M1: DNS for the domain. The debug-key fingerprint is in `assetlinks.json`; upload and Play signing keys come with the Play Console app.

## Next step

Push to GitHub and get CI green, then create the cloud projects. After that, M1 (NFC spike) needs DNS for the domain and two physical Android phones from different manufacturers.

## Risks

- The pinned toolchain is very new (TypeScript 6.0, Vitest 5, Sentry v11, Dart 3.13). The pins are held back where peer ranges require (ADR-0004).
- Goldens use Flutter's default test font, so they catch layout and colour regressions but not typography.
