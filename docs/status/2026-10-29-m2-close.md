# Status: M2 data and sync closed, 2026-10-29

Closed by the product owner after testing on a Pixel 9 Pro (Android 17) against the `development` Worker and the Supabase dev project. The two-device part of the exit test is still to be run (see Follow-ups).

## Done

**Backend:**

| Area | What was built | ADRs |
| --- | --- | --- |
| Schema | RLS on every table through `is_member`, the `change_xid` sync cursor, integrity rules | ADR-0014 |
| API contract | OpenAPI 3.1, with Zod validation in the Worker and a generated Dart client | ADR-0015 |
| Gateway | JWKS sign-in, the version gate (426), rate limits | ADR-0016 |
| Database access | Hyperdrive, as a dedicated role, with RLS on every query | ADR-0017 |
| Households and invites | Single-use codes stored as hashes; leaving; the last member deletes the household | ADR-0018 |
| Sync | Push with a change ledger and per-change results; pull by cursor; both one database call each | ADR-0019 |
| Live updates | One Durable Object per household | ADR-0020 |
| Sticker tokens | Freed as soon as their tag or household is deleted | ADR-0027 |

**App:**

| Area | What was built | ADRs |
| --- | --- | --- |

**Verified on the Pixel:**
- Google sign-in, staying signed in, and a tag cold start both signed in and signed out.
- Creating a household, invites, and "Live: connected".
- Adding a plant, watering and undo.
- Offline, then reconnecting.
- The sign-out warning, and data coming back after signing in again.
- Leaving, including deleting the household.

**Bugs found on the device and fixed, each with a regression test:**
- A sign-in right after signing out was undone by the slower sign-out.
- After sign-in, a tag cold start opened the plant list instead of the tag.
- After leaving, the app kept showing the household it had left (`asyncExpand` on a query that never ends).
- A change queued while leaving stayed queued forever.

**Decisions by the product owner:**
- Sign-in through external providers only, no email or password (ADR-0022).
- Sticker tokens are freed on delete (ADR-0027). Pre-written, locked stickers remain undecided, and AGENTS.md section 7 is unchanged.

## Follow-ups

- **The two-device exit test** needs a second Android device (the emulator with Google Play, or another phone) and a second Google test account. Steps are in ADR-0026: create, invite and join; a watering on one phone shows on the other within 5 seconds (NFR Sync, p95); offline edits on both phones agree after reconnecting. The same conflict rules are covered by automated two-device tests (ADR-0025).
- **The purge (open risk):**
  - Soft-deleted rows are never removed yet: deleted households with all their rows (by cascade), deleted plants, tags and undone waterings after 30 days, and ledger rows after 90 days.
  - NFR Privacy requires deletion to be complete within 30 days. Until the purge exists, deleted data stays.
  - Waiting for the product owner: build it now, or with the scheduled jobs in M5.
- **The sync test screen** has no widget test; Drift's live queries hang the fake test clock (ADR-0026). M4 replaces the screen.
- **The intermittent `live.test.ts` failure** in the Worker suite (once in 15 runs) hasn't been reproduced.
- **Windows with Smart App Control blocks SQLite in desktop tests,** so those run in Docker (README). CI runs on Linux.
- **The invite page needs the production Worker redeployed** for `plants.pampait.pl`.
- **Each hosted project needs:** `npx supabase db push`, the Data API turned off, the Email provider turned off, and the Google provider set up (docs/environments.md).
